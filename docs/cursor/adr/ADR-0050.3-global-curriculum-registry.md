# ADR-0050.3 — Global Curriculum Registry & Dynamic Curriculum Architecture

**Status:** Accepted  
**Date:** 2026-07-30  
**PR:** #50.3 Global Curriculum Registry & Dynamic Curriculum Architecture  
**Depends on:** ADR-0049, ADR-0050, ADR-0050.1, ADR-0050.2

## Context

PR #50–#50.2 established the Curriculum Import Engine and Jordan as the first reference dataset. The platform must now scale to unlimited countries and curricula without assuming Jordan’s grades, subjects, books, or semester model.

## Decision

1. **Global Curriculum Registry** is the permanent foundation:
   `World → Country → Curriculum → Academic Year → Grade → Semester? → Subject → Book → Unit → Lesson → ILE Package`.
2. Every object receives an **immutable Global ID** (`WLD/CTR/CUR/AYR/GRD/SEM/SUB/BOK/UNT/LSN/SKL/PKG`).
3. **Dynamic discovery** reads official curriculum sources; the platform never hardcodes a country’s subject set.
4. **Global Subject Registry** and **Global Skill Registry** remain the shared identity layers; countries only add aliases.
5. **Jordan is the first implementation**, not a hardcoded platform model.
6. **Knowledge graph foundation**: Lesson → requires → Lesson; Skill → depends on → Skill.
7. **Student foundation** is a data model only (Learning Path reserved; no AI).

## Consequences

- Physics/Chemistry/Biology appear for a grade only when present in that grade’s official source.
- Adding SA/EG/USA/AP/IGCSE/IB requires a new official source + connector aliases — not platform forks.
- ILE remains the only lesson runtime; this PR does not modify ILE, digital books, AI, or assessments.

## Alternatives rejected

- Hardcoding Jordan Grade 1 STEM (Physics/Chemistry/Biology) into the platform core.
- Per-country subject identity forks.
- Building AI tutor / quizzes / digital books inside the registry PR.
