# خطة التنفيذ التدريجية — SUCCESS OS

القواعد الحاكمة:

- الحفاظ على التصميم والبوابات وأسماء الصفحات وURLs وترتيب اللوحات والميزات الحالية.
- دفعة صغيرة واحدة في كل مرة مع تحقق وتقرير قبل المتابعة.
- عدم النشر التلقائي.
- عدم إدخال بيانات إنتاج وهمية.

## الدفعة 0 — استلام المشروع

الحالة: مكتملة مع قيود بيئة التشغيل.

- فحص التوثيق والإعدادات والشيفرة والمسارات وAPIs والاختبارات.
- تسجيل قيود بيئة التشغيل والنسخة المنشورة.
- إنشاء مستندات الاستلام الخمسة.
- إصلاح واحد فقط: سلسلة فلتر مكتبة الطالب في `book-filters.tsx`.
- تعذر تشغيل lint وtypecheck وbuild محليًا بسبب غياب Node.js وnpm؛ سُجّل ذلك بصدق.

## الدفعة 1 — أمن التسجيل

- اشتراط Firebase ID token في `POST /api/auth/register`.
- التحقق من تطابق decoded `uid` وemail مع الطلب.
- منع العميل من الادعاء بأنه OAuth أو اختيار provider.
- إضافة اختبارات تكامل للطلبات الصحيحة والمزورة والمكررة.

## الدفعة 2 — سجل Routes المركزي

- إنشاء registry مكتوب الأنواع للمسارات الثابتة والديناميكية وواجهات API.
- الحفاظ على جميع URLs الحالية.
- ترحيل `ROUTES` و`STUDENT_ROUTES` وdashboard paths تدريجيًا.
- إضافة اختبار يطابق registry مع ملفات App Router.
- إضافة crawler داخلي لاكتشاف 404 والروابط الميتة.

## الدفعة 3 — جودة وتشغيل

- توفير Node.js 20+ وnpm 10+ وGit.
- إنشاء lockfile موثوق.
- إصلاح scripts المتوافقة مع نسخة Next.js.
- إضافة Vitest أو Jest وReact Testing Library وPlaywright وaxe.
- إضافة unit وintegration وE2E وnavigation وlinks وaccessibility إلى CI.

## الدفعة 4 — رحلات المستخدم

- Student machine مستقلة.
- Job Seeker machine ولوحة مستقلة غير مشتركة مع الطالب.
- Partner machine لأنواع المعلم والمركز والمدرسة والجامعة والكلية وشركة التوظيف.
- حفظ السياق عند الرجوع.
- منع الإرسال المتكرر بمفاتيح idempotency.
- حالات loading وvalidation وerror وsuccess.

## الدفعة 5 — الهوية والتجارة والتفعيل

- ربط المنتجات والأسعار والطلب والدفع عبر adapter مزود.
- Webhooks موثقة وموقعة وidempotent.
- Entitlements وتفعيل مرتبطان بالمستخدم والمنتج.
- إشعارات حقيقية ناتجة عن domain events.
- عدم تخزين بيانات البطاقات داخل SUCCESS OS.

## الدفعة 6 — محرك المحتوى الأردني

- تعريف hierarchy الأردن ← النظام الوطني ← المرحلة ← الصف ← الفصل ← المادة ← الوحدة ← الدرس.
- سجل مصادر وحقوق واستخدام وإسناد.
- workflow مراجعة بشرية وتغطية أكاديمية 100%.
- عدم نسخ الكتب؛ استخدام مصادر رسمية وOER وكتابة أصلية.
- دمج المادة داخل رحلة الطالب الحالية دون زر مكتبة جديد.

## الدفعة 7 — الحصة المسجلة

- video asset موثق وقابل للتشغيل الفوري.
- حفظ timestamp واستئناف المشاهدة.
- transcript وترجمات وأهداف وشرح وأمثلة ورسومات ومسائل وملخص.
- ملاحظات وبطاقات وأسئلة واختبار وواجب وتحدٍ وتحليل أداء.
- إكمال server-side مرتبط بالمستخدم مع تزامن آمن.
- fallback لحالات الشبكة والفيديو غير المتاح.

## الدفعة 8 — AI Gateway

- عقد provider-neutral وadapters متعددة.
- routing وfallback وtimeouts وcircuit breaker.
- grounding على المحتوى الموثق فقط.
- حفظ assets المولدة وإصداراتها ومصادرها ومراجعاتها.
- قياس التكلفة والجودة والسلامة دون lock-in.

## بوابات القبول لكل دفعة

لا تعد الدفعة مكتملة إلا بعد:

- lint وformat check وtypecheck وproduction build.
- unit وintegration وE2E.
- navigation وbroken-link checks.
- accessibility.
- RTL/LTR على الجوال وسطح المكتب.
- تقرير الملفات والنتائج والمتطلبات الناقصة والمخاطر المتبقية.
